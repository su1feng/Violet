# 005 路线图

目标顺序：**先自己用起来，再开源。** 所以每一期都以"你自己愿不愿意每天用它"为验收，而不是功能数量。

## M0 · 闭环骨架（1–2 周）

不做界面。Telegram 就是界面。

**做：**

- 五张表 + `packages/store`
- `Engine` 最小子集：`receive` / `gate` / 建 ticket / `turnEnded` / `send`
- 一个执行器：claude
- Telegram 收发 + cron 触发
- 文件记忆：`MEMORY.md` 索引 + `tasks/` 按需读
- 排他锁保证单 worker

**明确不做：** `Assessor`（gate 只判断是不是你）、面板、webhook、沙箱、多执行器。

### 验收：五条，全部不用真模型

用假执行器就能跑，每条都是 `node --test`：

| # | 场景 | 断言 |
| --- | --- | --- |
| 1 | `kill -9` 打断 run，重启 | 消息不重、事件不丢 |
| 2 | scheduler 对同一 timer 触发两次 | 只出一条事件 |
| 3 | 同一条 Telegram 消息投递两次 | 只跑一次 |
| 4 | agent 提问 | 进程完全空闲（`ps` 里没有活跃 turn），回复后续上 |
| 5 | 没有新内容的一天 | 出站消息数**为 0** |

第 5 条是产品承诺的最小可验证形式。跑通这五条，M0 才算完——不是"跑起来能回话"。

## M1 · 授权与账本（3–5 周）

**做：**

- `Assessor` 接模型，三档 accept mode，默认 `observe`
- `outbox.reason` 分级 + attention 账本
- 面板：只读，列出"需要你的事"、账本、记忆
- 延迟提问完整链路（问题卡 → 作答 → 续同一会话）
- 记忆变更日志 + 一键撤销；写入前凭据脱敏

**验收：** 能回答"过去 30 天我发了 42 条，19 条你没点开，集中在哪一类"。答不出来，账本就没做成。

## M2 · 更多执行器（2–3 周）

- codex 适配器（用来验证接口）
- pi 适配器
- ACP 通用兜底 + `dsh --profile acp`
- `observe` 模式一个月的真实记录，决定是否开 `auto`

## M3 · 更多触发（3–4 周）

- 本地 webhook 接收器，幂等键，URL 一次性展示
- 订阅扇出：后续讨论自动到达正在处理的工作，不用再 @ 它
- 多 bot（每个一份记忆、一个工作目录）

## 之后再看

- 沙箱隔离（Docker 或 bubblewrap）
- `steer`（需要长驻会话，代价见 [004 执行器](004-executors.md)）
- 桌面壳
- 语音、浏览器、电脑控制

## 不做

见 [000 定位](000-positioning.md) 的"不做什么"。

## 里程碑的判断标准

每一期结束时问三个问题：

1. **它这周帮你做了什么？** 说不出具体的事，就是没做对。
2. **它这周打扰你几次，其中几次是值得的？** 比值下降才是进步。
3. **删掉哪个功能你会难过？** 答不出来的功能，是应该删的。
